# مراجعة أخطاء الباك إند والواجهة

## أين توجد السجلات؟

- Spring Boot يكتب إلى stdout/stderr داخل خدمة `api`. أضيف سجل لكل طلب: المسار دون query parameters، الطريقة، الحالة، المدة وRequest ID. يرسل الرقم في `X-Request-ID` حتى في رفض المصادقة.
- استثناءات API تسجل اسم الاستثناء والسبب ومواقع الكود، دون نص الاستثناء الذي قد يحتوي قيمًا من قاعدة البيانات. استجابات الأخطاء المتوقعة تبقى كما هي؛ الخطأ غير المتوقع يعيد رسالة عامة ورقم الطلب.
- Nginx يكتب طلبات الواجهة وطلبات البروكسي إلى stdout، والأخطاء إلى stderr. سجل الطلبات يتضمن رقم الطلب القادم من الباك إند.
- أخطاء JavaScript وReact لا تظهر تلقائيًا في سجل Nginx. تُجمع داخل التبويب في sessionStorage، بحد 50 حدثًا، ويمكن تنزيلها من زر «تقرير الأخطاء / Diagnostics» في الشريط العلوي. لا تُرسل تلقائيًا إلى خادم خارجي.
- إذا تعطّل React أثناء الرسم، تظهر صفحة بديلة بها زر تنزيل التقرير وإعادة المحاولة. إذا لم يتم تحميل JavaScript أصلًا، لن يعمل هذا الالتقاط؛ سجلات Nginx وأدوات المتصفح هي المرجع في هذه الحالة.

## مشاهدة السجلات مباشرة

من مجلد المشروع:

```bash
bash scripts/logs.sh api
bash scripts/logs.sh web
bash scripts/logs.sh db
```

اضغط Ctrl+C لإنهاء العرض فقط. دون تحديد خدمة يعرض السكربت الخدمات الثلاث. هذه سجلات حاويات Docker، وليست ملفات داخل `backend` أو `frontend`. أضيف تدوير لسجلات كل خدمة: 10 ميجابايت لكل ملف و3 ملفات.

## جمع ملف للمراجعة

1. بعد تحديث البرنامج، أعد فتحه وسجّل الدخول وكرّر الخطأ مرة واحدة.
2. اضغط «تقرير الأخطاء / Diagnostics» لتنزيل `mpos-browser-diagnostics.json`.
3. اجمعه مع سجلات الخدمات:

```bash
cd ~/Storage/mpos-testing/mpos-architecture
bash scripts/collect-logs.sh --browser ~/Downloads/mpos-browser-diagnostics.json
```

سيطبع السكربت مسار ملف `diagnostics/mpos-diagnostics-....tar.gz`. أرسل هذا الملف مع وصف الشاشة والفعل الذي سبّب المشكلة. إذا لم تستطع تنزيل تقرير المتصفح، شغّل `bash scripts/collect-logs.sh` وأرسل الأرشيف الناتج أولًا. نافذة التجميع الافتراضية 30 دقيقة، ويمكن استخدام `--since 2h`.

زر الواجهة يلتقط أيضًا الطلبات الناجحة والفاشلة وحالاتها والمسارات وأرقام الطلبات، دون bodies أو headers. لذلك يستطيع المراجع مطابقة `request_id` في `browser.json` مع `api.log` و`web.log`. الأخطاء التي حدثت قبل تثبيت هذا التحديث لن تظهر بأثر رجعي في تقرير المتصفح.

## محتويات التقرير وحدوده

يتضمن الأرشيف حالة الخدمات، وآخر 2000 سطر لكل خدمة ضمن النافذة، وإصدارات Docker/Compose، وتقرير المتصفح إن أرفقته. لا يجمع `.env` أو تفريغ قاعدة البيانات أو `docker compose config` أو Local Storage الخاص بتسجيل الدخول. يحاول إخفاء كلمات المرور المعرفة في `.env` وتوكنات Bearer وعناوين البريد. الإخفاء ليس ضمانًا لكل نص قد يكتبه مكوّن خارجي؛ راجع التقرير قبل مشاركته.

لا تُفعّل SQL parameter logging أو DEBUG عام لمعالجة الخطأ. التحديث لا يغيّر المخططات أو البيانات ولا يحل تلقائيًا أخطاء البزنس؛ الغرض الحصول على أدلة تحدد السبب ثم إصلاحه.

## إصلاح 400 عند فتح القوائم

أظهر السجل المرفق Invalid character found in the request target مع page[size] حرفية. هذا رفض من محلل HTTP في Tomcat قبل RequestLoggingFilter، لذا قد لا يظهر Request ID. الإصلاح في عميل Axios المشترك: ترميز الأقواس في query إلى %5B و%5D بعد تسلسل المعاملات. لا يحتاج تخفيف قواعد Tomcat أو تعديل Nginx. تشمل اختبارات الواجهة إرسال طلبات فعلية عبر Axios والتحقق من الرابط المرسل، وتشمل اختبارات API قراءة القوائم المرمّزة. الفحوص القديمة للمسارات دون معاملات لم تكن تكشف هذا الخلل.
