# المبيعات الأساسية — مرحلة التحويل الحالية

هذه المرحلة تنفذ فواتير المبيعات غير المحصلة. لا تشمل POS أو التحصيل أو المرتجعات الجزئية أو PDF أو الفاتورة الإلكترونية أو تقييم تكلفة المخزون. لا تستخدمها للمبيعات الفعلية قبل اكتمال هذه الوظائف واختبار القبول.

## حالات المستند

| الحالة | القيمة | أثر المخزون |
| --- | --- | --- |
| مكتمل | 1 | خصم الكميات مرة واحدة وقفل المستند |
| معلق | 2 | مسودة قابلة للتعديل، بلا حجز أو خصم |
| طلب بيع | 3 | مسودة قابلة للتعديل، بلا حجز أو خصم |
| ملغى | 4 | يعيد الكميات إذا كان مكتملًا؛ لا يعاد فتحه |

هذا قرار صريح في التحويل: مسودات البيع لا تخصم المخزون، بخلاف السلوك القديم الذي كان يخصم عند الإنشاء بغض النظر عن الحالة. إلغاء الفاتورة كاملة مختلف عن مرتجع جزئي. المستندات لا تُحذف حفاظًا على سجل التدقيق. إنشاء فاتورة بالحالة 1 يخصم فورًا؛ تعديل المسودة إلى 1 يتممها أيضًا.

الأموال BigDecimal بدقة أربع منازل HALF_UP، والخصم والضريبة الشاملة/المضافة والإجمالي تحسب في الخادم. لا يثق النظام بإجمالي مرسل من المتصفح. الوحدات حاليًا 1:1؛ لا يوجد تحويل كرتونة إلى قطع. الفواتير غير محصلة، وحقول paid_amount أو received_amount غير الصفرية مرفوضة. due_amount يصبح صفرًا عند الإلغاء دون تسجيل سداد.

## REST API

كل الطلبات تحتاج Bearer token وصلاحية manage_sale. القوائم في شاشة البيع تحتاج أيضًا صلاحيات العملاء والمنتجات والمخازن. ADMIN يحصل على الصلاحية عبر V4؛ الأدوار المخصصة يحدّثها المدير.

| المسار | الاستخدام |
| --- | --- |
| GET /api/sales | قائمة؛ page[number] وpage[size] حتى 100؛ filter[search] وstatus اختياريان |
| GET /api/sales/{id} | المستند والأصناف والإجمالي |
| POST /api/sales/preview | حساب الإجمالي دون حفظ |
| POST /api/sales | إنشاء؛ ترويسة Idempotency-Key إلزامية |
| PUT /api/sales/{id} | تعديل مسودة؛ version إلزامي بالقيمة المسترجعة |
| POST /api/sales/{id}/complete | الإتمام وخصم المخزون |
| POST /api/sales/{id}/cancel | الإلغاء وإعادة الكميات المخصومة |

مثال جسم الإنشاء (استبدل المعرّفات بمعرّفات بياناتك):

```json
{
  "customer_id": 1, "warehouse_id": 1, "date": "2026-11-14", "status": 2,
  "discount": 0, "tax_rate": 0, "shipping": 0, "notes": "اختبار",
  "sale_items": [{
    "product_id": 1, "product_price": 10, "quantity": 3, "sale_unit": null,
    "discount_type": 2, "discount_value": 0, "tax_type": 1, "tax_value": 0
  }]
}
```

أرسل مفتاح UUID جديدًا لكل فاتورة، وأعد استخدامه عند إعادة محاولة الطلب نفسه. تغيير الجسم بالمفتاح نفسه يرفض بـ409. تعديل مسودة بإصدار قديم يرفض بـ409. الأقفال تمنع طلبين متزامنين من استهلاك الرصيد نفسه. نقص أي صنف يرجع المعاملة كاملة، بما فيها رأس الفاتورة وحركات الأصناف الأخرى. إتمام أو إلغاء المستند نفسه مرة ثانية لا يكرر الحركة.

## اختبار يدوي بعد التحديث

1. أنشئ عميلًا ومنتجًا ومخزنًا تجريبيين. أضف رصيدًا افتتاحيًا 10 للمنتج في المخزن من شاشة المخزون.
2. أنشئ بيعًا معلقًا بكمية 3 وسعر 10، دون ضرائب أو خصومات. الإجمالي 30 والرصيد يظل 10.
3. اعرض المستند ثم أتممه. الرصيد يصبح 7، وتظهر حركة SALE مرتبطة بـsale_id.
4. أعد طلب الإتمام عبر API. الرصيد يظل 7. لا يسمح بتعديل المستند المكتمل.
5. ألغِ المستند. الرصيد يرجع 10 وتظهر SALE_CANCEL. إعادة طلب الإلغاء لا تغيره.
6. حاول إتمام بيع بكمية 11. يجب رفضه دون إنشاء حركة أو إنقاص الرصيد.
7. تحقق من عرض العربية والإنجليزية، ومن حساب الإجماليات، ومن القائمة بعد تحديث المتصفح.

اختبارات Java تغطي الدورة والتزامن ومنع التكرار والتراجع وصلاحيات API وترقية V3 إلى V4. التفاعل في المتصفح وتشغيل Docker لهذه الحزمة يحتاجان تحققًا على جهازك. عند ظهور خطأ، نزّل تقرير Diagnostics وشغّل scripts/collect-logs.sh كما في docs/diagnostics-ar.md؛ لم يصل تقرير بالأخطاء السابقة بعد.
