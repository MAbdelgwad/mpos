# إصلاح عرض المنتجات ومسار الباركود

كان جدول المنتجات يشترط وجود رمز عملة غير فارغ قبل تجهيز الصفوف، بينما الإعداد الافتراضي في Spring فارغ. أصبحت الصفوف مستقلة عن تحميل إعدادات العملة، مع عرض السعر دون رمز عند عدم تحديده.

أصبح مسار print/barcode مسموحًا في وضع Spring مع بقاء صلاحية manage_products مطلوبة. تستخدم الشاشة باركود المنتجات القادم من API. كتالوج QR للمنتجات التجريبية متاح منفصلًا في /images/demo/index.html.

لتطبيق حزمة mpos-products-barcode-fix.zip على النسخة الحالية:

```bash
unzip -o ~/Downloads/mpos-products-barcode-fix.zip -d ~/Storage/mpos-testing
cd ~/Storage/mpos-testing/mpos-architecture
docker compose -p mpos-test-architecture up -d --build --no-deps web
bash scripts/verify.sh
```

حدّث صفحة المتصفح باستخدام Ctrl+Shift+R. لا حاجة إلى إعادة إدخال البيانات أو إعادة تشغيل سكربت seed-demo. هذه حزمة تحديث للواجهة وليست نسخة مستقلة.

افتح /#/app/products وتحقق من ظهور المنتجات، ثم /#/app/print/barcode. اختر المخزن، ثم المنتجات ومقاس الورق، ثم المعاينة والطباعة. لطباعة QR للبيانات الاسترشادية افتح /images/demo/index.html.

التحقق: نجح بناء الواجهة مع تحذيري CSS سابقين، ونجح 17 اختبار Node منها اختبارات عرض المنتجات عند فراغ العملة أو عدم وصول الإعدادات، واختبارات الوصول لمسار الباركود والصلاحيات. تعذر تشغيل Chromium في البيئة بسبب رفض إنشاء socket، لذا تتطلب معاينة الطباعة والطباعة الفعلية اختبارًا محليًا. لا تعديل على الباك إند أو قاعدة البيانات.
