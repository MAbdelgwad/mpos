# تحويل MPOS إلى Spring Boot وPostgreSQL

## القرارات المعتمدة

- الإبقاء على واجهة React الحالية.
- قاعدة PostgreSQL جديدة؛ لا يوجد ترحيل لبيانات تشغيل في هذا النطاق.
- إضافة الخلفية الجديدة داخل `backend` على فرع مستقل، مع الحفاظ على المشروع الأصلي للمقارنة.
- REST API مع مراعاة عقود الاستجابة التي تعتمد عليها React.

## نتيجة فحص المصدر

مرجع المراجعة: `3523ab98266d9aa8f8b64e6c83dbf31c4109374e`.

المشروع يستخدم PHP/Laravel 10 وReact 17، وإعداد قاعدة البيانات الافتراضي MySQL. يحتوي شجر المصدر على 42 ملف Model مباشر و85 ملف Migration. تمت مراجعة dependencies وroutes/api.php ونماذج المنتجات والمخازن والعلامات التجارية، ومنطق تسجيل الدخول وأجزاء من منطق المبيعات واستدعاءات React. هذه مراجعة أولية وليست تدقيقًا كاملًا لكل قاعدة عمل.

| المجال | المصدر الأصلي | العمل المطلوب |
| --- | --- | --- |

## ما نُفذ في هذه الدفعة

أساس Java 21 وSpring Boot، قاعدة PostgreSQL تُنشأ بـFlyway، Docker Compose، تسجيل الدخول والخروج، رموز تنتهي بعد ساعتين ومخزنة كتجزئة، حساب إداري ابتدائي من متغيرات البيئة، وإدارة المخازن. الاختبارات تغطي الشكل المتوقع للاستجابة والعربية والتحقق والتكرار والصلاحيات وانتهاء الرموز وإلغاءها.

**التحويل الكامل غير منجز. لا تُستخدم هذه الدفعة بدل النظام التشغيلي.** React لم تُربط بالخلفية الجديدة بعد؛ استدعاءات permissions/settings/config/dashboard بعد الدخول ما زالت تحتاج تنفيذًا. لم تنقل صورة مخزن أو بيانات غير موجودة في نموذج Warehouse الأصلي.

## ترتيب استكمال التحويل

1. استكمال عقود تشغيل React: إعدادات الواجهة واللغة والمستخدم والصلاحيات، ثم فصل البناء والاستضافة عن Laravel Mix/Blade.
2. نقل المنتجات والوحدات والعلامات والتصنيفات والعملاء والموردين والمرفقات.
3. بناء حركات المخزون والمشتريات، والتحقق من تحويل الوحدات وقفل الأرصدة المتزامنة.
4. نقل المبيعات والمدفوعات والمرتجعات والكاشير والتعليق والخصومات؛ مقارنة أمثلة حسابية مع التنفيذ القديم.
5. نقل عروض الأسعار والمصروفات والتقارير والتصدير والإعدادات.
6. اختبار end-to-end من React إلى PostgreSQL، واختبار Docker والنسخ الاحتياطي والاستعادة قبل اعتماد البديل.

تستخدم المبالغ `BigDecimal` و`numeric` في الوحدات المالية القادمة. يجب تحديد التقريب وموضع الخصم وضريبة الصنف وضريبة الفاتورة من الكود واختبارات المطابقة، وليس افتراض نسبة ضريبة واحدة أو فرض عملة جديدة. تُعالج عملية الفاتورة والمخزون والدفع بمعاملة واحدة مع منع تكرار الطلب. لا تُضاف SaaS/multi-tenancy ضمنيًا؛ لم يطلبها المستخدم لهذا التحويل.

## معايير قبول البديل الكامل

- كل شاشة ومهمة موجودة في المصدر لها API بديل أو قرار موثق بشأنها.
- تطابق إجماليات الفواتير والضرائب والخصم والمدفوعات والمرتجعات في حالات مرجعية.
- لا ينتج البيع المتزامن مخزونًا سالبًا، ولا يُسجل دفع/بيع مرتين عند إعادة الطلب.
- صلاحيات الخادم فعالة حتى عند تجاوز الواجهة.
- التشغيل عبر Docker وإعادة التشغيل يحافظان على البيانات والمرفقات.
- نجاح سيناريوهات البيع والشراء والمرتجع والطباعة والتقرير من الواجهة الحالية.

## تحديث الدفعة الثانية

تم تنفيذ البيانات الأساسية (التصنيفات والعلامات والوحدات والعملاء والموردين والمنتجات)، والصور والباركود، وإدارة المستخدمين والأدوار والصلاحيات وإعدادات الشركة. تعمل شاشات React الحالية ببناء مستقل واستضافة Nginx، مع توجيه `/api` إلى Spring Boot. رابط التشغيل المحلي عبر Compose هو `http://localhost:8081`.

أضيفت صفحة للبيانات الأساسية وإعدادات الشركة، وحُجبت أدوات الاستيراد والتصدير والعمليات غير المنقولة في وضع Spring. تم إصلاح نقل Bearer token ومعالجة أخطاء الشبكة والحفاظ على رقم المنفذ. لا توجد حركات مخزون بعد؛ كميات المنتجات الجديدة صفر، وإضافة الرصيد الافتتاحي من نموذج المنتج محجوبة إلى حين تنفيذ المشتريات والمخزون.

الجداول الإضافية في V2: roles، permissions، role_permissions، brands، product_categories، base_units، units، customers، suppliers، products، media، ui_settings. العلاقة المركبة بين وحدة المنتج ووحدتي البيع والشراء تُفرض داخل PostgreSQL. لا تغييرات على V1.

المرحلة التالية: دفتر حركات المخزون والمشتريات والأرصدة الافتتاحية، ثم المبيعات والدفع والمرتجعات. الاستضافة داخل Docker ما زالت تحتاج تحققًا في بيئة بها Docker؛ اختبار المتصفح المرفق مصمم لاستخدام خادم محلي مؤقت مع الخلفية وقاعدة البيانات الفعليتين، لكن تشغيل Chromium تعطل بسبب قيود البيئة؛ لذلك لم تُثبت دورة التشغيل الكاملة من المتصفح بعد.

## تحديث الدفعة الثالثة

نُفذت المشتريات (مسودات/استلام/إلغاء)، والأرصدة الافتتاحية، والتسويات والتحويلات، وسجل الحركة والأرصدة الفعلية للمنتجات. شاشات جديدة في وضع Spring متاحة من الشريط العلوي. الاستلام فقط يزيد المخزون، والإلغاء حركة عكسية مع الاحتفاظ بالمستند. الحسابات دقيقة بأربع منازل، ومنع التكرار والتزامن مغطى باختبارات PostgreSQL.

تفاصيل قواعد العمل واختلاف حالة الاستلام عن المصدر وخطوات التجربة في `inventory-purchases-ar.md`. المبيعات والمدفوعات والمرتجعات وتقييم المخزون المحاسبي والتقارير ما زالت متبقية.
